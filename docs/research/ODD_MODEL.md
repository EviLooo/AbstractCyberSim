# Model description for graduation review

Status: implemented software specification, not expert-validated realism. Read
with APPROVED_SCOPE.md, the requirement ledger and PLAN_SOURCE_AUDIT.md. This
describes enterprise_cc4_research, schema 2.0; historical profiles have different
rules. The organization is the experimental treatment, not a hidden world input.

## Purpose and entities

Study how concrete hierarchy and swarm implementations coordinate investigation,
combine complementary capabilities and recover after a simulated defensive
change. Compare programmed and, after separate authorization/qualification, LLM
decision policies. A programmed win is valid evidence; an LLM win is not assumed.

The pinned CC4 engine supplies enterprise hosts, processes, users, services,
interfaces, sessions, subnets and native action execution. Our compiler chooses
entry, bridge, maintenance archive, application and two possible protected target
roles inside that larger fixed scaffold. Background hosts remain visible when
legitimately discovered but cannot provide an unintended access shortcut. This
is a finite recipe system, not an arbitrary network generator.

An attacker worker has its own active native sessions, privilege, controller
scan caches, possessed opaque simulation references and private evidence memory.
An owned controller can originate remote operations; an owned privileged shell
can become a new controller through EstablishPivot. Merely hearing a host name
does not grant a session, privilege, cache or permission to use another worker's
source. Account references are simulation objects, with hidden validity/scope;
they are neither real credentials nor strings sent to a real machine.

The hierarchy's coordinator has no native session. Its state consists of reports
that actually arrived, public rules and assignments. A swarm worker has local
claims and delivered reports; there is no global swarm allocator. The message
bus is a research communication overlay, separate from simulated service traffic.
Blue agents provide native coverage and execute one shared-budget response.

## State, units and initial conditions

Time is a joint native tick, not seconds. One tick advances all workers together.
An action can remain busy for several ticks; a busy worker makes no extra model
decision. Durations are declared research costs, not measured incident times:
scan 1, inspection 2, web/weak-account access 4, token login 2, privilege/pivot 2;
connectivity probe 1, service/authentication probe 2. Native Restore takes 5.
See packages/contracts/research_catalog.py for the authoritative public manual.

The v1 world has hidden compatibility conditions and persistent prerequisites.
There is no arbitrary per-attempt success probability. A retry cannot turn an
incompatible service into a compatible one. Seeded role placement, conditions
and cached-reference validity generate different causal combinations. World seed
also changes native addresses; address changes alone are not new mechanisms.
The event seed namespace is recorded but the current bounded defender has no
stochastic event generator. Do not claim random environmental transitions.

One worker is a single/independent control; two and four are core team sizes.
Common entry gives identical entry placements across organizations. Matched split
entry places alternating workers at the two declared entry hosts; it is unavailable
to one worker. The protected targets are fixed native host names in v1. The
compiler independently permutes bridge/archive role bindings with the recipe seed.

## Scheduling and interactions

backend/app/runs.py is the shared UI/headless loop. At each joint tick it:

1. Advances private clocks and delivers due overlay messages subject to capacity,
   expiry and topology. Only verified delivered evidence grants native intel.
2. Supplies each available worker its private evidence and public mechanical
   candidates. The hierarchy can assign from delivered reports; swarm access
   intentions wait for actual delivery before a local claim election.
3. Validates the selected action's owned source/session and records decisions.
   Admission reserves one shared access attempt. Failures retain that cost.
4. Runs one native joint step. Blue selects a response from earlier reachable
   protected-host service traffic and its own coverage, without a compromise-state
   or organizational oracle. Busy actions finish through native execution.
5. Updates each worker's own observations, queues newly generated reports/claims,
   scores actual target access/hold, saves the frame and checks terminal limits.

Source predicates are rechecked on completion. A patch during a pending action
can invalidate it. Unfinished admitted work is retained as partial/unknown, not
reported as a completed failure or refunded. Scheduler seed and execution order
are saved. Frozen native phase policy stays fixed through the declared horizon;
it does not inherit historical CC4's phase changes.

## Observation, adaptation and submodels

Mechanical candidates know the public rules and visible ownership; they include
potentially incompatible methods. They never filter using hidden token validity,
compatibility, a witness route or future defender state. The policy decides how
to investigate. Notes contain limited local leads, fallible account claims and
opaque references. Only owned readable artifacts can be inspected; root-only
records require native privilege. Diagnostic probes disclose source-specific
handshake/timeout, import behavior or SSH authentication methods. An authentication
probe does not disclose whether a password is weak.

Observation delay is 0–2 ticks. Original observation and recipient delivery times
remain distinct. Age/stale threshold 4–12 is a policy input, not a hidden truth
oracle. Relaying the same immutable evidence ID does not refresh its observation
time. Scan caches are actor/controller-specific. Verified reports can transfer a
disclosed account reference, but cannot transfer the source controller needed to
use it. Contradictory old/new records remain auditable.

Recipes:

| Recipe | Mechanism | Required software evidence |
| --- | --- | --- |
| linear_control | Compatible short workflow | A repeated workflow may succeed; no difficulty claim |
| investigate | Initially similar worlds require distinguishing probes/methods or new account records | Same initial inputs, useful different evidence, persistent unchanged failure |
| combine | Bridge permission and a separately obtained reference jointly enable a target; second target provides parallel work | Neither capability alone suffices; verified relay plus own source succeeds |
| recover | One observed-traffic response invalidates compatibility or removes access | Native Patch or Restore, changed evidence or own loss, legal recovery |

Patch removes the import property in active/backup service processes while
preserving the listening port and existing sessions. Restore uses the native
action to remove access and associated cache; qualifying target hold can reset.
Only one response is available across Blue. The core allows patch OR Restore,
not both on the same host. Entry hosts are excluded. Signal/decision/effect logs
are researcher-only; attackers learn through their own changed observations.

Patch has duration1/priority0; exact same-tick completion follows CC4's recorded
joint execution order. Own session permission loss is immediate local status;
external observations may arrive later. Worked source-checked trajectories and
archives: WORKED_MECHANISMS.md and examples/worked/. No reviewer approval yet.

The fixed workflow has declared priorities and bounded retries. The evidence
controller retains negative hypotheses in its own access epoch, refreshes failed
formerly-positive methods and uses actually delivered session reports to avoid
duplicate team acquisition. The observed planner searches bounded graphs of
visible prerequisites with explicitly optimistic unknown estimates. These are
simulator-specific programmed policies, not representative of all rule systems.
LLMs receive the same public catalog, evidence and gateway, without these rankings.

## Outcomes, qualification and limits

Win means actual active qualifying privileged sessions on declared targets for
the configured hold duration. Reaching an address or collecting a reference is
insufficient. The declared native horizon, shared access ceiling and model team
budget apply to failures too. Coordinator and repair calls count. Recipient-copy
bytes, unknown costs, intervention, refusal, invalid decision, context overflow,
technical errors and interrupted work remain recorded separately.

Every evaluation initialization runs an isolated legal native feasibility witness.
It neither advances the evaluated episode nor supplies knowledge to a competitor.
Unverified worlds are excluded before policy performance is interpreted. A witness
proves that the bounded configured task can be legally completed; it does not
prove that an observation-limited policy will discover the route or that the model
is behaviorally realistic. See METRIC_DEFINITIONS.md for event reducers.

Behavioral source mapping is in PLAN_SOURCE_AUDIT.md and revised-plan sections
6–12: partial observability, capability dependencies, bounded response and delayed
coordination motivate abstractions. Particular notes, costs, passwords, topology
and timers are design choices, not empirical calibration. Green activity,
operational payloads, real targets, arbitrary topology, full defender learning,
cloud infrastructure and native checkpoint restoration are outside this scope.
Software qualification is not expert review, scientific superiority or publication
novelty. Use REVIEW_WORKSHEET.md before stronger behavioral claims.
