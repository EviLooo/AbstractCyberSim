# Programmed controls and equal-information boundary

Research catalog `minimal_access_v1`, programmed policy version1.0 (development,
freeze exact source before any held-out study). Historical local_rules/replan/search
retain their older catalogs. These are competent simulator-specific controls;
their success is an accepted result, not evidence that every rule system works.

All research workers receive the same public rule manual, eligible mechanical
candidate list, owned native source/cache/token information, local delivered
evidence, fallible notes, original observation/receipt times, public mission and
resource ceilings. Hidden compatibility, token validity, role inventory, witness
and pending defender events are absent. Every decision uses the same native
gateway. LLMs receive these facts and public rules without a programmed ranking.

`fixed_workflow`: inspect local readable artifacts, maintain privilege/controller,
scan known addresses and try web_rfi, ssh_weak_auth, then available token login
in that fixed order. It ignores diagnostic response and artifact prose when
ranking methods, and does not use the evidence controller's lead priority.
Public ownership, known addresses and actually possessed references still bound
eligibility. Completed attempts have finite configured retry count/backoff.
This is the repeated-workflow control, not the only non-LLM comparator.

`evidence_controller`: uses source-specific current import/authentication probes;
an auth response does not prove password weakness. An artifact's claimed token
scope justifies an unverified login hypothesis. Failed unchanged methods and
negative probes are retained in the own-access epoch; aging alone does not prove
a repair. Own access loss opens a new investigation epoch. A previously positive
failed import method triggers a fresh probe. Prioritize disclosed task leads
before incidental background and known mission privilege before optional
inventory. Fresh delivered peer ownership claims defer duplicate acquisition,
but expire and transfer no native capability. See GRADUATION_DECISIONS D09–D16.

`observed_planner`: uses that evidence filtering plus bounded uniform-cost paths
through observed scan/diagnostic/method/privilege prerequisites. Unknown method
compatibility and privilege success are explicitly optimistic assumptions.
Token routes require a possessed reference with a disclosed claimed scope.
Public durations weight the path; maximum128 expansions per source/target.
This is a partial next-goal estimate, not a global team optimum, a calibrated
probability model, or proof that a plan meets the entire mission deadline.
Estimated future actions still undergo actual admission and completion checks.

Hierarchy has a sessionless leader using delivered reports only, and finite
leader-issued intent reservations. Swarm uses local claims, actual delivery
before access election and no shared allocator. The architecture is a concrete
organizational treatment, not hidden world information. Count all leader/worker/
repair calls and recipient copies. Same native count/access placement, tick and
attempt limits, model settings and team resource ceilings define a matched pair.
The team_cap_one sensitivity gates the same proposals after cognition, charges
decisions even when capacity suppresses the proposal, and makes no cognition
call for an already busy worker. Record native ticks separately from latency.

Bounded native method/value/recovery and mocked provider fixtures qualify
implementation, not generalization or a scientific ranking. Live Qwen remains
unqualified after its prior first-request error; mock success is not substituted
for a live result. Scientific single/independent/organization comparisons are
prepared by configuration and require separate authorized study execution.
